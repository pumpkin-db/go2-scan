### Depot 结论（2026-08-26 审查后勘误版，替代原「定稿」）

1. **ARiADNE @ Depot 三跑一致的模式**：开跑 ~116-144s 狂奔 65-79m（0.56m/s 连续）
   → rl_planner 效用全零 + 地图静止 20s → 停滞式判定宣布「探索完成」 → 站桩剩余
   97% 时间。ER 冻结在 43.5/49.2/48.0%。三跑 plateau 全部落在旧判废线
   （<5%×duration=105s）之上擦边逃废；评估器判废线已收紧至 15%（2026-08-26），
   重算脚本 tools/recompute_path_length.py 判定三跑均 degraded=True。
2. **核心未解问题 = 为什么 ~2 分钟后效用全零**（任务#11）：ER 仅 ~48%，场景内仍有
   大量可达未知区，规划器却无候选目标。这是当前第一优先级，优先于上楼/天花板讨论。
3. **天花板数字 56.8%/76.2%/57.1%(z>4.5m) 降级为「估计值」**：计算脚本不存在、
   参数未留痕、不可复现（审查A1）。待 scenes/gtools/compute_er_ceiling.py 用与
   评估器同款可见性模型重算后方可引用。「唯一路径=上楼」的归因叙事同步悬置。
4. **path_length 口径澄清**：trajectory_5hz 存档口径下罚站噪声含水率仅 ~1%
   （67.24→67.22m），「路径长严重注水」的说法不成立；但该指标无法区分
   「有效探索移动」与「无效走动」，需配合 moving_ratio 阅读。

## 关键发现

1. **同参数下跑与跑差异巨大**（530m / 11.5m / 318m）——PROGRESS.md 预警的
   「6m/res0.2 组合会卡顿/过早完成」被定量证实：成功率 2/3。退化跑的特征信号 =
   ER 平台期来得极早（run2 是 28s）+ 路径长异常短，可用作自动判废指标。
   （2026-08-26 注：Depot 三跑证明还有一种逃过此判据的故障模式——「~2min 正常
   探索后规划器失明站桩」，已用 15% 判废线 + moving_ratio 堵住。）
2. **成功跑基线（run3）**：T90=476s、T95=678s、平台期 685s（≈11.4min，比赛 10min
   预算附近）；318m 路径；ER 99.6% vs scan Recall@0.2 95.2%——理论可见与实际建图
   差 4.4pt，指标体系自洽 ✅。
3. 地图质量：中位误差 0.046m，Precision@0.2≈80%（边缘残影拉低），Recall@0.2≈95%
   ——成功跑的建图质量对比赛「完整度」维度非常有利。
4. run1 的 Recall@0.2=94.9% 与 run3 的 95.2% 高度一致 → 地图质量指标跑间稳定，
   适合做 A/B 的主指标；ER/路径长则区分好跑坏跑。

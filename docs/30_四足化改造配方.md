# 30 · 「无人机→四足」改造配方（ego-planner vs SCAN-Planner diff 提取，2026-08-18）

> 用途：FUEL 决策层地面化时照此配方改。证据为 diff -rq + grep（SCAN-Planner 行号）。

## SCAN-Planner 相对 EGO-Planner 的七类改动

1. **执行出口换地面**：删 `traj_server`（无人机轨迹服务）→ 加 `closed_loop_controller.cpp`（bspline→100Hz `geometry_msgs/Twist` /cmd_vel，xy 位置 P 控制+yaw 跟踪，max_vyaw 限 1.0）+ 仿真件 `go2_kinematic_sim`/`go2_gait_publisher`/`open_loop_controller`。
2. **z 压平**：优化器代价梯度 z 行清零 `bspline_optimizer.cpp:1154,1182`（`grad_3D.row(2).setZero()`）→ 只水平变形，垂直轮廓由上层给。
3. **A* 2.5D 化**：xy 扩展、z 起终点线性插值 `dyn_a_star.cpp:167,234`（interpolateZIndexOnSearchPlane）。
4. **地图滑窗化+双位姿输入**：`grid_map.cpp:14-26`（sliding 10×10×5、local_update_range、map_sliding_thresh）、`:130-145`（sensor_pose 射线投射 + body_pose 滑窗中心）、`:306-323`（updateSlidingMap）。
5. **碰撞体双圆柱**（yaw 感知机身包络）：查询入口 `grid_map.h:364-373 getInflateOccupancy(pos,yaw)`=查 pos±offset·heading 两点；参数 `grid_map.cpp:23-24`、膨胀 `:192-202`；优化器调用点 `bspline_optimizer.cpp:82,278,725,748,763,883,1010,1105`（yaw 由 estimateControlPointYaw 估）。
6. **FSM 重写接口层**：`ego_replan_fsm` → `scan_replan_fsm`，状态骨架保留（INIT/WAIT_TARGET/GEN_NEW_TRAJ/REPLAN_TRAJ/EXEC_TRAJ/EMERGENCY_STOP，scan_replan_fsm.cpp:536），加 navi_mode 1/2/3 目标接口。
7. **核心不动**：B 样条优化主循环、梯度下降优化器、uniform_bspline、poly_traj 基本原样（diff 仅可视化/容器小改）。

## 套用到 FUEL 的改法（四类）

① 输出端：FUEL 发 `/planning/bspline` 给 so3 控制器 → 改发 `nav_msgs/Path`→`/initial_path`（或直接接 closed_loop_controller）；
② z 地面化：视点 z 钳到体高度、TSP/A* 代价里的飞行时间/yaw 机动换地面距离/限速（FUEL 的 ViewNode::costTo 与 esdf_slice_height_ 是飞行模型重灾区）；
③ 地图接口：FUEL 的 ESDF 点云输入改接 FAST-LIO `/cloud_registered`+`/Odometry`（参照 fastlio_integration.launch 接法）；
④ 决策核心（FIS frontier、簇视点、LKH TSP、execute-review）**原样保留**。

依赖提醒：FUEL 调外部 **LKH** 解 TSP（fast_exploration_manager.cpp:343-383 写 TSPLIB 文件调 `LKH` 可执行）——需用户下载 LKH-3.tgz 并 make。

## 已落地（2026-08-18，fuel_ws 编译 ✅）

**环境类**：
- nlopt 2.7.1 装本地 `new_algorithm/nlopt-prefix`；`bspline_opt/CMakeLists.txt:12-13` 硬编码改指本地（迁 Linux 需再改）。
- 官方 `lkh_tsp_solver`（在 FUEL utils/ 内，作者漏放 LKH 源码）：补 LKH-3.0.14 的 SRC/*.c（删 LKHmain.c）+ SRC/INCLUDE/*.h；新版 LKH API 补第二参 0（HasFitness/AddToPopulation/ReplacementIndividual/ReplaceIndividualWithTour）；删 *.HUNT.c 备选实现；删 lkh_tsp 可执行目标。
- `swarmtal_msgs` 兼容消息包自写（仅无人机执行层用，运行时不用）。
- `quadrotor_msgs` 复用 ego-planner 本地副本。

**改造类**：
- ① 输出接口：`fast_exploration_fsm.h` 加 `path_pub_`；`fast_exploration_fsm.cpp` 构造里 advertise `/initial_path`；PUB_TRAJ 分支把 `fd_->newest_traj_`（B 样条）按 0.3s 采样成 nav_msgs/Path 发布。
- ② z 压平：发布路径 z=0（高度由 SCAN-Planner body_height 处理）。

**未落地**：③ 代价模型地面化（ViewNode::costTo 飞行时间→地面距离；只影响视点排序质量，不阻塞功能）；④ 传感器接驳。

**④ 判定（2026-08-18，探针定位）**：FUEL 在「仿真+狗」环境**不通，判为数据不匹配而非参数问题**——探针实测前沿种子 817 个真实存在但簇太小被滤（深度图仅覆盖前向 5×4m 扇区、1Hz；点云入口缺最远点合成）；且原设计假设相机随无人机任意朝向+高清深度+精确位姿，三项都不满足。**决定：FUEL 闭环弃用**，探索层用弓形/STC（已通）+ 后续简单前沿。真机 MID360 与仿真深度相机量级差距过大，仿真修不好。
